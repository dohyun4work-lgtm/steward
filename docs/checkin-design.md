# DH Task Hub — 하루 체크인 알림 설계안 v2

검토용 설계 문서. 구현 코드 없음.

**v2 변경 (ChatGPT 검토 반영)**: ① 18시 재조정 / 21시 마감 역할 구분 ② "모두 내일로" 마감 경고 ③ claimed·sending 만료와 재시도 정책. 그 외 설계는 v1과 같음.
기존 UI(하단 네비 5개, TODAY/THIS WEEK, 시트 구조)와 `tasks` 테이블은 **변경하지 않음**. 새 테이블 4개와 화면 3개(체크인 시트 2종, 하루 복기)만 추가.

---

## 0. 알림 구성

| 시간 | 종류(kind) | 목적 | 눌렀을 때 |
|---|---|---|---|
| 09:00 | `morning` | 오늘 할 일 보기·추가 | TODAY + 아침 카드 |
| 12:00 | `midday` | 중간 체크 | 남은 업무 + 빠른 추가 |
| 15:00 | `midday` | 중간 체크 | 남은 업무 + 빠른 추가 |
| 18:00 | `evening` | 저녁 재조정 | 오늘 안에 할 일만 남기기 (한 장씩) |
| 21:00 | `evening_final` | 중간 체크 + 남은 업무 정리 | 위와 같음 + "남은 것 모두 내일로" |
| 23:00 | `review` | 하루 복기 | 요약 + 한 줄 복기 + 내일 가장 중요한 일 |

화면 종류는 4개(kind)이고, 시간은 사용자가 바꿀 수 있는 "슬롯"으로 분리한다. 같은 종류를 두 번 써도 됨(12시·15시 모두 midday).

알림 문구는 **개수만** 넣고 업무 제목은 넣지 않는다. 잠금 화면에 교회 업무·개인 일정이 그대로 노출되지 않게.

```
09:00  오늘 할 일 6개 · 기한 초과 1
12:00  남은 업무 4개 · 지금 정리하거나 추가하세요
18:00  남은 업무 3개 · 오늘 안에 할 것만 남겨요
21:00  남은 업무 2개 · 내일로 넘기고 오늘을 마무리해요
23:00  오늘 완료 7개 · 하루를 1분만 돌아봐요
```

## 1. 알림별 사용자 흐름

### 09:00 아침 — TODAY

```
알림 탭 → TODAY 화면 (기존 그대로)
┌─────────────────────────────┐
│ 10월 8일 (목)        [오늘|이번 주]│
├─────────────────────────────┤
│ 좋은 아침이에요                  │  ← 아침 카드 (이 알림으로 들어왔을 때만)
│ ★ 오늘 가장 중요한 일             │
│   주보 최종 검토        [완료]    │  ← 어제 23시에 정한 일 (있을 때만)
│ 기한 초과 1 · 오늘 6 · 확인 필요 1 │
│ [＋ 추가]  [인박스 3 정리]  [닫기] │
├─────────────────────────────┤
│ 기한 초과 / 오늘 / 확인 필요 (기존) │
└─────────────────────────────┘
```
- 카드는 닫거나 목록을 조작하면 접힘. 같은 날 다시 열면 안 보임.
- **탭 수**: 알림 1 → (필요하면) 추가 1.

### 12:00 · 15:00 중간 체크 — 남은 업무 + 빠른 추가

```
알림 탭 → TODAY + 중간 체크 시트 (반쯤 올라옴)
┌─────────────────────────────┐
│ 중간 체크 · 15:00     남은 4 / 완료 3 │
│ ○ 시설보수 견적 회신   기한 초과    │
│ ○ 주보 최종 검토                │  ← 남은 업무만 (기한 초과 + 오늘)
│ ○ Arms of Love QC             │     동그라미 = 완료 (기존과 동일)
│ ○ 사진 선별 확인                │
│ [ 생각난 일 바로 추가…     ] [추가]│  ← 입력창 상주, 키보드는 자동으로 안 올림
│                     [확인 완료]│
└─────────────────────────────┘
```
- 입력창에 쓰면 기존 빠른 추가와 같은 규칙 (기본값 "오늘").
- 행을 탭하면 기존 상세 시트.
- [확인 완료] 또는 시트를 닫으면 체크인 완료로 기록.
- **탭 수**: 확인만 하면 2 (알림 + 확인 완료).

### 18:00 · 21:00 — 역할 구분 (v2)

| | 18:00 재조정 | 21:00 마감 |
|---|---|---|
| 질문 | "오늘 안에 할 수 있나?" | "오늘을 어떻게 끝낼까?" |
| 목표 | 남은 저녁 시간에 할 일만 오늘에 남기기 | **오늘 버킷을 비우고** 하루 닫기 |
| 화면 형태 | 한 장씩 카드 (하나씩 판단) | 목록 한 화면 (한눈에 보고 한 번에 처리) |
| 기본 선택 | [오늘 유지]가 첫 버튼 | [내일]이 첫 버튼, "오늘 유지" 없음 |
| 일괄 처리 | 없음 | "남은 것 모두 내일로" |
| 끝나면 | TODAY로 복귀, 남긴 업무가 오늘에 그대로 | "오늘 마무리 완료" + 23시 복기 안내 |

**18:00 재조정 — 한 장씩**

```
┌─────────────────────────────┐
│ 저녁 재조정          1 / 3     │
│ 오늘 안에 할 수 있나요?          │
│   주보 최종 검토               │
│   TLC · 오늘 마감              │
│ [오늘 유지] [내일] [대기] [완료]  │
│                    건너뛰기 › │
└─────────────────────────────┘
```

**21:00 마감 — 목록 한 화면**

```
┌─────────────────────────────┐
│ 오늘 마무리      완료 7 · 남음 3 │
│ ○ 시설보수 견적 회신  기한 초과   │
│      [내일] [대기] [다른 날]     │
│ ○ 주보 최종 검토     오늘 마감   │
│      [내일] [대기] [다른 날]     │
│ ○ 택배 반품                    │
│      [내일] [대기] [다른 날]     │
├─────────────────────────────┤
│ [남은 3개 모두 내일로]           │
│ 오늘 밤에 끝낼 거예요 ›           │  ← 작은 링크, 아무것도 안 바꾸고 닫기
└─────────────────────────────┘
```
- 동그라미 = 완료 (기존과 동일). 처리한 행은 목록에서 빠짐.
- "다른 날" = 기존 미루기 시트 (다음 주·날짜 선택·나중에).
- 목록이 비면 "오늘 마무리 완료" → 23시 복기 시간 안내.

| 버튼 | 처리 |
|---|---|
| 완료 | `complete_task` RPC (기존) |
| 오늘 유지 (18시만) | 변경 없음, 다음 카드로 |
| 내일 | `do_date = 기준일 + 1`. 마감일은 그대로 |
| 대기 | 기존 대기 시트(대상·확인일) |
| 다른 날 (21시만) | 기존 미루기 시트 |

- 대상: 기한 초과 + 오늘 버킷 (확인 필요는 기존 [받음] 흐름 유지).
- **탭 수**: 18시 업무 하나당 1. 21시 전부 넘기면 2 (알림 + 모두 내일로, 마감 업무가 있으면 +1 아래 경고).

### "모두 내일로" — 마감 경고 (v2)

21시 화면과 23시 복기의 "남은 것 모두 내일로"에 공통 적용.
옮길 업무 중 **기한 초과**나 **오늘 마감**이 있으면 바로 옮기지 않고, 같은 시트 안에서 확인 단계를 보여줌 (브라우저 확인창 사용 안 함).

```
┌─────────────────────────────┐
│ 마감이 있는 업무가 있어요         │
│ 기한 초과 1 · 오늘 마감 1        │
│ • 시설보수 견적 회신 (10/6 마감) │
│ • 주보 최종 검토 (오늘 마감)      │
│ 내일로 옮겨도 마감일은 바뀌지 않고 │
│ 내일 TODAY에 기한 초과로 표시돼요.│
│                             │
│ [마감 있는 것 빼고 옮기기]        │  ← 첫 버튼 (안전한 쪽)
│ [모두 내일로]                   │
│ [취소]                         │
└─────────────────────────────┘
```
- 마감 업무가 없으면 경고 없이 바로 옮기고 되돌리기 토스트.
- "마감 있는 것 빼고 옮기기"를 고르면 마감 업무만 목록에 남아 개별 판단.
- 어느 쪽이든 마감일(`due_date`)은 절대 자동 변경하지 않음.

### 23:00 하루 복기

```
알림 탭 → 하루 복기 화면 (전체 시트)
┌─────────────────────────────┐
│ 10월 8일 (목) 돌아보기           │
│ 완료 7 · 남음 2                 │
│ ▸ 완료한 일 7 (접힘)             │
│ ▾ 남은 일 2                     │
│   ○ 증명서 앱 문구    [내일] [대기]│
│   ○ 택배 반품        [내일] [대기]│
│   남은 것 모두 내일로 (마감 경고 적용)│
├─────────────────────────────┤
│ 오늘 한 줄                       │
│ [ 주보 마감 전에 원고를 먼저…  ]   │  ← 선택, 300자
├─────────────────────────────┤
│ 내일 가장 중요한 일               │
│ ( ) 주보 최종 검토               │  ← 내일 할 일·남은 일 중 선택
│ ( ) 셀 교재 인쇄 파일 전달         │
│ [ 새로 입력…              ]     │
│                   [저장하고 마치기]│
└─────────────────────────────┘
```
- 저장 시: `daily_reviews` 한 행 저장. 고른 업무는 `do_date = 내일`로 (이미 내일이면 그대로).
- 새로 입력하면 `tasks`에 `status=active, do_date=내일`로 생성 후 연결.
- 다음 날 09시 아침 카드에 "★ 오늘 가장 중요한 일"로 표시.
- 별표(`starred`)는 건드리지 않음 — "내일 가장 중요한 일"은 하루짜리 지정이라 별표와 의미가 다름.
- 모든 항목 선택. 아무것도 안 하고 [저장하고 마치기]만 눌러도 됨.
- **탭 수**: 최소 2 (알림 + 저장).

## 2. 필요한 DB 테이블

`tasks`는 변경 없음. RLS 원칙(본인 행만, anon 접근 불가)은 기존과 동일.

### 2-1. `checkin_slots` — 알림 시간표

| 컬럼 | 타입 | NULL | 비고 |
|---|---|---|---|
| id | uuid | NO | PK |
| user_id | uuid | NO | 기본 auth.uid() |
| kind | text | NO | morning / midday / evening / evening_final / review |
| local_time | time | NO | 한국 시간 기준, 분 단위 |
| weekdays | smallint[] | NO | 0(일)~6(토), 기본 전체 |
| enabled | boolean | NO | 개별 ON/OFF |
| created_at, updated_at | timestamptz | NO | |

- UNIQUE (user_id, local_time) — 같은 시각에 두 개 금지.
- 처음 로그인 시 기본 6개 생성.

### 2-2. `notification_prefs` — 전체 설정 (사용자당 1행)

| 컬럼 | 타입 | NULL | 비고 |
|---|---|---|---|
| user_id | uuid | NO | PK |
| enabled | boolean | NO | 전체 알림 ON/OFF |
| timezone | text | NO | 'Asia/Seoul' (지금은 고정, 나중 확장용) |
| updated_at | timestamptz | NO | |

### 2-3. `push_subscriptions` — 기기별 푸시 구독

| 컬럼 | 타입 | NULL | 비고 |
|---|---|---|---|
| id | uuid | NO | PK |
| user_id | uuid | NO | |
| endpoint | text | NO | **UNIQUE** (같은 기기 중복 등록 방지) |
| p256dh | text | NO | 구독 암호화 키 |
| auth | text | NO | 구독 인증 키 |
| device_label | text | YES | "iPhone", "사무실 PC" 등 (설정 화면 표시용) |
| created_at | timestamptz | NO | |
| last_success_at | timestamptz | YES | |
| failure_count | smallint | NO | 연속 실패 수 |
| disabled_at | timestamptz | YES | 만료(404/410)·연속 실패 시 |

- 앱 사용자: 본인 구독 조회·등록(upsert)·삭제 가능.
- 발송은 Edge Function(service_role)만.

### 2-4. `notification_log` — 발송 기록 + 중복 방지

| 컬럼 | 타입 | NULL | 비고 |
|---|---|---|---|
| id | uuid | NO | PK, deep link에 포함 |
| user_id | uuid | NO | |
| slot_id | uuid | NO | checkin_slots 참조 |
| kind | text | NO | 발송 시점 kind 기록 |
| local_date | date | NO | 이 알림이 속한 한국 날짜 |
| status | text | NO | claimed / sending / sent / partial / failed / unknown / expired / skipped |
| claimed_at | timestamptz | NO | 마지막 선점 시각 |
| sending_started_at | timestamptz | YES | Edge Function이 발송을 시작한 시각 |
| next_attempt_at | timestamptz | YES | 재시도 가능 시각 |
| sent_at | timestamptz | YES | |
| attempts | smallint | NO | 선점 횟수 (최대 3) |
| devices_sent | smallint | NO | 성공한 기기 수 |
| error | text | YES | |
| opened_at | timestamptz | YES | 알림 눌러 들어온 시각 |
| completed_at | timestamptz | YES | 체크인 완료(확인 완료/정리 끝/복기 저장) |

- **UNIQUE (slot_id, local_date)** — 핵심 중복 방지 (7번).
- 앱 사용자: 본인 기록 조회, `opened_at`/`completed_at`은 RPC로만 기록.

### 2-5. `daily_reviews` — 하루 복기

| 컬럼 | 타입 | NULL | 비고 |
|---|---|---|---|
| user_id | uuid | NO | |
| review_date | date | NO | 복기 대상 날짜 |
| note | text | YES | 300자 이하 |
| top_task_id | uuid | YES | 내일 가장 중요한 일, tasks 참조 (삭제 시 NULL) |
| done_count | smallint | NO | 저장 시점 스냅샷 |
| open_count | smallint | NO | 저장 시점 스냅샷 |
| created_at, updated_at | timestamptz | NO | |

- PK (user_id, review_date) — 하루 1개, 다시 저장하면 덮어씀.
- 아침 카드는 `review_date = 오늘 - 1`인 행의 `top_task_id`를 읽음.

### 2-6. 추가 RPC (설계만)

| 함수 | 용도 |
|---|---|
| `ensure_default_slots()` | 첫 로그인 시 기본 6개 슬롯 + prefs 생성 (이미 있으면 무시) |
| `mark_checkin(log_id, 'opened' \| 'completed')` | 본인 기록만, 한 번만 기록 |
| `save_daily_review(date, note, top_task_id, new_title)` | 복기 저장 + 새 업무 생성 + do_date 조정을 한 트랜잭션 |
| `claim_due_checkins()` | Cron 전용. 보낼 슬롯을 찾아 log에 claimed로 선점 (7번) |
| `checkin_summary(user, date)` | 알림 문구용 개수 (오늘·남음·완료·기한 초과) — 기존 `today_items` 재사용 |

"모두 내일로"는 기존 `tasks` UPDATE 한 번 (`id in (...)`)으로 충분 — 새 RPC 불필요. 단, 반복 업무도 do_date 변경은 허용되므로 문제 없음.

## 3. Deep link 구조

GitHub Pages 정적 호스팅이라 **해시 라우팅** 사용 (서버 설정 없이 동작).

```
https://<앱 주소>/#/checkin/<kind>?d=<local_date>&n=<log_id>
```

| 슬롯 | 주소 | 열리는 화면 |
|---|---|---|
| 09:00 | `#/checkin/morning?d=2026-10-08&n=…` | TODAY + 아침 카드 |
| 12:00, 15:00 | `#/checkin/midday?d=…&n=…` | TODAY + 중간 체크 시트 |
| 18:00 | `#/checkin/evening?d=…&n=…` | TODAY + 정리 시트 |
| 21:00 | `#/checkin/evening_final?d=…&n=…` | 위 + "모두 내일로" |
| 23:00 | `#/review?d=2026-10-08&n=…` | 하루 복기 |

일반 화면도 같은 방식으로 주소를 가짐: `#/today`, `#/today/week`, `#/inbox`, `#/waiting`, `#/archive`, `#/settings`.

**`d`(날짜)를 넣는 이유**: 알림을 늦게 누를 수 있어서.

| 상황 | 처리 |
|---|---|
| 같은 날 누름 | 정상 |
| 체크인 알림(09~21시)을 다음 날 누름 | TODAY로 열고 "어제 알림이에요" 한 줄만. 정리 시트는 띄우지 않음 |
| 23시 복기를 자정 넘어 누름 | **`d`의 날짜(어제)를 복기**. "내일" = `d + 1` = 실제 오늘. 날짜는 앱의 오늘이 아니라 `d` 기준 |

**알림 탭 처리 (서비스 워커)**
1. 알림을 누르면 서비스 워커가 열려 있는 앱 창을 찾음.
2. 열려 있으면 그 창을 앞으로 가져오고 주소만 전달 → 앱이 해당 화면으로 이동.
3. 없으면 그 주소로 새로 열기.
4. 앱이 `n`(log_id)로 `mark_checkin(n, 'opened')` 호출.

## 4. Supabase Cron + Edge Function + Web Push 구조

```
pg_cron (매분)
   │  select claim_due_checkins()      ← DB 안에서 끝남. 보낼 게 없으면 여기서 종료
   │  보낼 게 있으면 → pg_net으로 Edge Function 호출 (claimed log id 목록 전달)
   ▼
Edge Function: send-checkins  (service_role, VAPID 개인키 보유)
   │  1. log id별로 status='claimed'인 것만 처리 (재호출돼도 안전)
   │  2. checkin_summary로 개수 계산 → 문구 생성
   │  3. 사용자의 활성 push_subscriptions 전체에 Web Push 발송
   │  4. 결과 기록: sent / partial / failed, 만료 구독은 disabled
   ▼
기기 (서비스 워커)
   │  push 이벤트 → 알림 표시 (tag = kind+날짜)
   │  notificationclick → 3번 deep link 처리
```

**왜 이 구조인가**
- 매분 Edge Function을 부르지 않음. 보낼 게 있을 때만 호출 → 하루 6회 + 재시도 정도.
- 선점(claim)을 DB에서 원자적으로 하므로 Cron이 겹쳐도, Edge Function이 재시도돼도 한 번만 발송 (7번).
- 앱은 지금처럼 Supabase에 직접 연결. 알림 발송만 서버에서.

**보안**
- Cron → Edge Function 호출에는 공유 비밀값을 헤더로 보냄. 비밀값은 Supabase Vault에 저장.
- Edge Function은 이 비밀값이 맞을 때만 동작. 외부에서 주소를 알아도 발송 못 함.
- VAPID 공개키: 앱에 넣음(공개해도 됨). 개인키: Edge Function 비밀값에만.
- 푸시 내용에는 개수와 deep link만. 업무 제목 없음.

**발송 옵션**
- TTL(유효 시간): 체크인 30분, 복기 2시간. 기기가 꺼져 있다가 한참 뒤 켜졌을 때 지난 알림이 몰려 뜨지 않게.
- urgency: high (iOS·Android에서 제때 도착하도록).

**구현 시 확인할 것**
- Deno(Edge Function)에서 쓸 Web Push 라이브러리 호환성은 구현 단계에서 최신 상태를 확인하고 선택.
- pg_cron, pg_net 확장 활성화 필요 (Supabase 대시보드에서 켬).

## 5. 알림 개별 ON/OFF와 시간 변경

**위치**: 기존 UI 유지를 위해 하단 네비는 그대로 두고, **보관 탭 맨 아래(지금 "샘플 초기화"가 있는 자리)에 "설정"** 진입점 추가. 아침 카드에도 작은 "알림 설정" 링크.

```
┌─────────────────────────────┐
│ 알림                          │
│ 전체 알림                 [ON]│
├─────────────────────────────┤
│ 이 기기                        │
│ 알림 받는 중 · iPhone   [테스트]│  ← 또는 [이 기기에서 알림 켜기]
│ 다른 기기: 사무실 PC     [삭제] │
├─────────────────────────────┤
│ 09:00  아침 · 오늘 할 일   [ON]│
│ 12:00  중간 체크           [ON]│
│ 15:00  중간 체크           [ON]│
│ 18:00  남은 업무 정리       [ON]│
│ 21:00  정리 · 마무리        [ON]│
│ 23:00  하루 복기           [ON]│
│ 매일 · 일요일 제외 등 요일 설정 › │
└─────────────────────────────┘
행 탭 → 시간 선택 + 요일 칩 (월 화 수 목 금 토 일)
```

**규칙**
- 시간은 5분 단위 선택. 같은 시각 두 슬롯 금지(UNIQUE).
- 종류(kind)는 슬롯마다 고정. 시간만 변경 — 화면 목적이 바뀌지 않게.
- 오늘 이미 보낸 슬롯의 시간을 바꿔도 오늘 다시 보내지 않음 (log의 slot+날짜 기준).
- 아직 안 보낸 슬롯을 현재 시각 이후로 바꾸면 오늘 새 시간에 발송. 이미 지난 시각으로 바꾸면 오늘은 건너뜀.
- 전체 OFF: 슬롯 설정은 그대로 두고 발송만 중단.
- 변경은 즉시 저장 (기존 자동 저장 원칙).

## 6. iOS / Android PWA 조건

## 7. 중복 발송 방지 — 5겹

| 단계 | 장치 | 막는 상황 |
|---|---|---|
| 1. 선점 | `notification_log` **UNIQUE (slot_id, local_date)** + `INSERT … ON CONFLICT DO NOTHING` | Cron이 겹쳐 실행, 같은 분에 두 번 호출 |
| 2. 상태 | Edge Function은 `claimed → sending` 조건부 전환에 성공한 log만 처리 | Edge Function 재시도·중복 호출 |
| 3. 시간 창 | 슬롯 시각 ~ +20분 안에서만 선점·재시도. 지나면 `expired` | 서버 장애 후 복구 시 지난 알림 몰아 보내기 |
| 4. 기기 | `push_subscriptions.endpoint` UNIQUE | 같은 기기가 두 번 등록돼 두 번 받음 |
| 5. 표시 | 알림 `tag = kind + 날짜` | 그래도 두 번 도착하면 기기에서 하나로 덮어씀 |

### 선점 만료(timeout)와 재시도 정책 (v2)

`claimed`나 `sending`에서 멈춘 기록이 영구히 남지 않도록 상태별로 만료 규칙을 둔다.

```
claimed ──(Edge Function이 잡음)──▶ sending ──▶ sent / partial / failed
   │                                  │
   │ 3분 안에 안 잡힘                    │ 5분 안에 안 끝남
   ▼                                  ▼
failed (claim timeout)              unknown (발송 여부 불확실)
   │ 재시도 대상                         │ 재시도 안 함
```

| 상태 | 의미 | 만료 | 다음 |
|---|---|---|---|
| claimed | 선점만 됨, 아직 발송 시작 전 | 3분 | `failed`로 바꾸고 재시도 대상 (아무 기기에도 안 갔으므로 안전) |
| sending | Edge Function이 발송 시작 | 5분 | `unknown`. **재시도하지 않음** (일부 기기에 이미 갔을 수 있어 중복보다 누락을 택함) |
| failed | 전체 실패 또는 claim timeout | - | 아래 조건이면 다시 선점 |
| partial | 일부 기기만 성공 | - | 재시도 안 함 (성공한 기기에 또 가지 않게) |
| expired | 시간 창(슬롯 시각 +20분) 지남 | - | 종료 |

**재시도 조건** (모두 만족)
- status = `failed`
- attempts < 3
- 지금 ≥ next_attempt_at (실패 후 2분 간격)
- 슬롯 시각 + 20분 이내 (지나면 `expired`)

**정리 주체**: 매분 도는 `claim_due_checkins()`가 선점 전에 만료 처리부터 수행. 별도 작업 불필요.

**Edge Function 쪽 규칙**
- 시작할 때 `claimed → sending`을 조건부 UPDATE로 바꾸고, 바꾸는 데 성공한 log만 발송 (두 번 호출돼도 한쪽만 진행).
- 발송이 끝나면 결과를 기록. 함수가 도중에 죽으면 위 `sending` 만료 규칙이 처리.
- 기기 표시 단계에서 `tag` + 다시 울리지 않음 설정을 써서, 혹시 같은 알림이 두 번 와도 소리 없이 하나로 덮어씀.

**선점 조건 정리** (`claim_due_checkins`, 매분)
- prefs.enabled = true, slot.enabled = true
- 오늘(한국) 요일이 weekdays에 포함
- 지금(한국) ≥ local_time, 지금 < local_time + 20분
- 활성 구독이 1개 이상
- 오늘 이 슬롯의 log 없음

## 8. 앱을 오래 열어두어도 날짜가 바뀌면 정상 동작

**문제**: 프로토타입은 화면을 그릴 때만 오늘 날짜를 계산. 탭을 밤새 열어두면 다음 날에도 어제 기준 TODAY가 보임.

**구조**
1. **시계 모듈 하나**: "오늘(한국)"은 이 모듈만 계산. 기기 시간대가 달라도 `Asia/Seoul` 기준 (DB의 `app_today()`와 일치).
2. **다시 확인하는 순간**
   - 앱이 다시 보일 때 (`visibilitychange`, `pageshow`, `focus`) — 휴대폰에서 앱을 다시 여는 대부분의 경우
   - 자정 + 몇 초에 맞춘 타이머
   - 1분마다 가벼운 확인 (백그라운드에서 타이머가 멈췄다 깨어나는 경우 대비)
3. **날짜가 바뀌었으면**
   - 서버에서 업무 다시 불러오기 → TODAY 다시 그리기
   - 열려 있는 정리·중간 체크 시트는 닫고 "날짜가 바뀌었어요" 토스트
   - 상세 시트·입력 중인 내용은 유지 (작성 중인 메모를 잃지 않게)
   - 빠른 추가의 "오늘/내일/이번 주" 칩 날짜도 새로 계산
4. **날짜가 안 바뀌어도** 앱이 다시 보일 때 업무를 다시 불러옴 → 다른 기기(PC↔휴대폰)에서 바꾼 내용 반영.
5. **deep link의 `d`가 우선**: 복기 화면은 앱의 오늘이 아니라 `d` 날짜 기준. 자정 넘어 복기해도 "내일 가장 중요한 일"이 하루 밀리지 않음.
6. **서버 기준 재확인**: 날짜 경계 근처(23:55~00:05)에는 화면용 계산과 별개로 서버 `get_today()` 결과를 기준으로 표시.
